# 性能

[English](Performance)

### 预算

`copia-bench` 会在临时存储中写入 1,000 条卡片（其中 300 张图片），任何一项超出预算即失败。CI 在每次推送时运行它。

| 指标 | 预算 |
|---|---|
| 空闲 CPU（卡片栏隐藏） | 60 秒平均 < 0.1% |
| 空闲内存（phys_footprint） | < 40 MB |
| 卡片栏打开时的内存 | < 120 MB |
| 从 ⌘Y 到第一帧 | 50 次打开的 p95 < 100 ms |
| 隐藏的卡片栏 | 释放卡片视图和缩略图 |

### 结果

使用默认参数（空闲 60 秒、打开 50 次）在 M3 Pro、macOS 27.2、release 构建下测得，卡片栏位于 5848 × 2448 显示器上：

| 指标 | 结果 |
|---|---|
| 空闲 CPU | 0.029% |
| 空闲内存 | 33 MB |
| 卡片栏打开 | 38 MB（滚动浏览全部 1,000 条后为 53 MB） |
| 从 ⌘Y 到第一帧 | p50 67 ms，p95 94 ms |

### 保持轻量的方法

- **只做轮询。** 空闲时唯一的工作是在一个有容差的计时器上每 0.5 秒读取一次 `changeCount`。
- **隐藏即释放内存。** 关闭卡片栏会丢弃卡片视图并清空缩略图缓存；窗口和宿主视图保留，因此下次打开很快。
- **小缩略图，在主线程之外解码。** 缩略图在后台任务中以 384 px 解码（足够 2× 显示器上 192 pt 的卡片），放入上限为 24 MB 的缓存。卡片从不保留自己的副本。
- **只有一层玻璃，使用系统阴影。** 卡片栏只有一层玻璃背景；窗口阴影由窗口服务器在 Copia 的内存之外绘制。
- **图片后面不用 `Canvas`。** 玻璃卡片栏中的 SwiftUI `Canvas` 棋盘格曾占用约 110 MB 的 GPU 缓冲区。现在改用 16 × 16 的平铺图片。

### 运行基准测试

```sh
swift build -c release --product copia-bench
"$(swift build -c release --show-bin-path)/copia-bench" --json bench.json
```

选项：`--idle SECONDS`（默认 60）、`--opens N`（默认 50）、`--width POINTS` 把卡片栏放在较窄的区域中。运行期间捕获处于暂停状态，因此不会读取你复制的任何内容。

### 限制

- 打开延迟在进程内测量：从切换到窗口上屏后的第一次提交帧。用 ScreenCaptureKit 测量实际呈现的帧需要屏幕录制权限，不在 CI 中运行。
- macOS 没有按进程的 GPU 时间计数器；“隐藏”通过面板不在屏幕上、且卡片和缩略图已释放来检查。
